  # Catalog Capture (Android)

  An Expo / React Native app for capturing product data into the Ventrie
  catalog. A collector scans a barcode, fills in the product details, and files
  the result as a submission for a moderator to review.

  Built against the `internal-backend` catalog API (`/api/catalog/*`).

  ## Requirements

  - Node.js 20+
  - A running `internal-backend` instance
  - Android Studio with an AVD, or a physical Android device

  ## Setup

  ```bash
  npm install
  cp .env.example .env
  ```

  Then set `EXPO_PUBLIC_API_URL` in `.env` to the backend as seen *from the
  device running the app* — not from your workstation:
`
  | Target            | Value                          |
  | ----------------- | ------------------------------ |
  | Physical device   | `http://<machine-LAN-IP>:8080` |
  | Android emulator  | `http://10.0.2.2:8080`         |
  | iOS simulator     | `http://localhost:8080`        |

  `localhost` on Android means the phone itself, so it never reaches your
  server. `10.0.2.2` exists only inside the emulator — from a real phone it
  routes nowhere, and an unroutable address is dropped rather than refused, so
  requests hang instead of failing. That shows up as a form stuck on
  "Loading...".

  Expo reads this value at bundle time, so restart `expo start` after changing it.

  ## Running

  ```bash
  npm run emulator     # start the Android emulator (see note below)
  npm run android      # build and install a debug build
  npm start            # Metro only, against an already-installed build
  ```

  `npm run emulator` launches the emulator outside VS Code's process tree via
  `systemd-run --user --scope`. Started from the integrated terminal, qemu
  inherits VS Code's systemd scope, grows to 5–6 GB, and the OOM killer takes
  down the editor instead of the emulator. Pass an AVD name to override the
  default (`Small_Phone`):

  ```bash
  npm run emulator Pixel_10_Pro_Fold
  ```

  Other scripts:

  ```bash
  npm run typecheck        # tsc --noEmit
  npm run android:release  # release variant
  npm run prebuild:clean   # regenerate the native android/ folder
  ```

  ## How it works

  Three screens, routed by local state in [App.tsx](App.tsx) — there is no
  navigation library:

  1. **Scan** — read a barcode with the camera, or skip straight to the form.
  2. **Add** — enter product details, attributes, variants, and photos.
  3. **Review** — read back what was just captured.

  ```
  src/
    api/          one request helper + React Query hooks per endpoint
    components/   shared inputs (dropdowns, tag input, category picker)
    features/
      product/    the three screens, their hooks, validation, and payload shaping
    lib/          category tree flattening, client id generation
    theme/        colors and shared styles
    types/        catalog and product shapes
  ```

  Reference data (verticals, categories, brands, manufacturers, attributes) is
  fetched from the backend and cached by React Query. Queries retry once rather
  than the default three times — with an 8s per-request deadline, three retries
  with backoff leave the form loading for over half a minute before reporting
  anything.

  Captures are held in an in-memory store
  ([submissionStore.ts](src/features/product/submissionStore.ts)) that lives
  outside React so it survives screens unmounting. It is **not** persisted —
  closing the app drops anything not yet sent.

  Photos upload to `/api/catalog/media/upload`, which stores them in Cloudinary.
  Completed captures POST to `/api/catalog/product-submissions` and land in the
  moderator queue as `pending`.

  ## Notes

  - Android only in practice. The iOS and web scripts exist but are untested.
  - `android/` is generated by `expo prebuild` and git-ignored; run
    `npm run prebuild` after changing native config in `app.json`.
  - `usesCleartextTraffic` is enabled so the app can talk to a plain-HTTP dev
    backend over the LAN.
